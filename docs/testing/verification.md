Rust 최종 검사는 실제 번들 리소스를 사용했다. 초기 리소스 준비 전 검사에서 썼던 테스트용 override를 최종 검증에는 사용하지 않았다. 빌드 중 생성한 브라우저 미리보기 adapter는 production JS에 포함하지 않는다.

## 전달물

- `artifacts/My-Brush-0.3.0-macOS-arm64.zip`: 로컬 검증용 macOS 앱. ad-hoc 서명이며 Developer ID 공증본은 아니다.
- `artifacts/My-Brush-0.3.0-source.zip`: 최종 기능·문서를 반영한 소스 사본(Git 이력 제외). Windows PC에서 압축을 풀고 README의 준비 절차와 `scripts/verify-windows.ps1`을 실행한다.
- `artifacts/SHA256SUMS.txt`: 전달 ZIP의 체크섬.
- 바이너리와 임시 로그는 Git에 넣지 않는다. 리모트·push·공개 업로드는 수행하지 않았다.

## v0.2 사용성·그리기 확장 (2026-09-08)

- 순서대로 도구막대 이동·접기, 기본값/현재 도구 분리·프리셋, 화살표·형광펜을 구현했다.
- 브라우저 UI에서 도구막대 하단 이동 시 색상창 상단 배치, 접힌 상태 새로고침 복원, 프리셋 저장·불러오기와 기본 12px 복귀, 설정창 이름 Enter 저장을 확인했다.
- 형광펜으로 텍스트를 강조한 뒤 화살표 추가, 화살표 머리 지우기, 실행 취소 복원 시 객체 수가 1→2→1→2로 바뀌는 것을 확인했다.
- 추가 자동 검사: 위치 범위·잘못된 저장값 복구, 기본값과 현재 도구 분리, v2→v3 마이그레이션, 프리셋 슬롯 보존·검증, 화살표 방향/머리/퇴화 좌표, 형광펜 단일 획 투명도·fade alpha·새 필기 보존.
- 종속 패키지는 추가하지 않았다. 버전 변경으로 바뀐 잠금 파일 해시를 의존성 고지에 반영했고 303개 패키지의 고지 일치를 확인했다.

### v0.2 실제 macOS 확인

- 설치 경로 `artifacts/My Brush.app`를 최종 release로 교체하고 ad-hoc 서명을 검증한 뒤 실행했다. Info.plist와 실제 UI 모두 v0.2.0이며 준비 완료 상태다.
- 제어창에서 2560×1440/100% 기본 모니터 → 2940×1912/200% 모니터 → 기본 모니터 선택이 오류 없이 반영됐다. 두 번째 모니터의 필기 좌표·DPI 정확도까지 검증한 것은 아니다.
- 실제 오버레이에서 형광펜·화살표 작성, 실행 취소·다시 실행 결과가 1→2→1→2개로 반영됐고 렌더링을 확인했다.
- 빨간 4px 프리셋을 적용해도 기존 설정 파일은 노란 14px 그대로였다. 같은 조합을 2번 슬롯에 저장한 뒤 파일에서 v3·프리셋 3개와 시작 기본값 14px 보존을 확인했다. 시작 기본값 복귀 시 노란 14px를 표시했다.
- 도구막대를 접은 채 Cmd+,로 설정을 연 뒤 그리기로 돌아오면 접힌 상태와 2개 필기가 유지됐다. 다시 펼친 뒤 실제 앱의 Shift+2 입력으로 빨간 4px가 적용됐다.
- 도구막대 전체 삭제 후 입력을 받는 도구막대가 사라지고 설정창은 ‘사용 준비 완료’를 표시했다. 전역 Option+X의 물리 키·OS 포커스 복귀 반복 검사는 이 기록으로 대체하지 않는다.
- 검증 중 그린 객체는 전체 삭제했고 현재 도구는 기존 시작 기본 펜으로 돌려놓았다. 기존 색·굵기·단축키 및 프리셋 초기 구성은 보존했다.
- 화면 끝 펼침 너비 및 비동기 모니터 선택값 보존을 별도 수정 커밋으로 남겼다. 실제 앱 검증은 두 수정을 포함한 최종 빌드에서 수행했다.

## v0.3 강의 사용성 확장 (2026-09-08)

순서대로 한글 도구 키·측정 도구 보강, 필기 숨김·복원, 선택한 화면 삭제, 커서 강조·클릭 표시를 기능별 커밋했다. 설정 기본값은 그대로 보존했다(이 기기의 기존 저장값은 노란 14px, 새 설치 기본값은12px).

### 실제 앱에서 확인한 범위

- 최종 macOS arm64 release의 Info.plist·시작 UI 모두0.3.0, 준비 완료. 새 도구막대와 C 키의 커서 켜짐 상태·노란 강조 원을 확인했다.
- 동일 기능 코드에 임시 전환 로그만 추가한 검사 빌드에서 기본 모니터에 한 획을 작성했다. 숨김 버튼을 누르면 선·도구막대가 사라지고 입력을 받지 않는 창 상태로 바뀌었다. 제어창의 ‘숨긴 필기 다시 표시’를 누른 뒤 그리기로 돌아오면 같은 선1개가 복원됐고 undo0개→redo1개로 기록 보존을 확인했다.
- ‘이 화면만 지우기’ 후 비입력 창으로 전환되고, 재진입0개→undo1개를 확인했다. 다른 화면의 진행 중 편집 보존 및 선택/전체 삭제의 혼합 세대·undo/redo 범위는 Rust 검사로 검증했다. 두 화면에 실제 선을 그린 교차 검증은 아직 완료하지 않았다.
- 실제 선택을 100% 기본 화면→2940×1912/200% Retina→기본 화면으로 바꾸고 기존 기본 화면의 선이 남는 것을 확인했다. Retina 캡처에서 검사 도구의 ScreenCaptureKit -3811 오류가 발생해 해당 화면의 실제 필기·커서 좌표 판정은 보류했다.
- macOS 입력 소스가 두벌식 한글인 상태에서 T 키로 텍스트 도구가 선택되는 것을 확인했다. 한글 문장의 직접 조합·마지막 받침 확정은 완결된 검사로 기록하지 않는다.
- 자동 검사 중 수동 입력이 섞여 상태가 달라졌다. 임시 로그에서 문제 삼았던 모드 복귀 시점은 삭제 명령 경로였고, 추적 구간에서 시간만으로 삭제되는 경로는 관찰하지 않았다. 원인을 추측해 제품 동작을 바꾸지는 않았다.
- 검사 로그 코드는 제거했고 일반 release를 다시 설치했다. 최종 release의 그리기 진입0개→Esc 입력 복귀를 다시 확인했다. 검사 도구·개발 서버는 배포물에 포함하지 않는다.

### 남아 있는 실기 확인

- 물리 전역 키 반복, 앱 조작 중 커서 클릭 표시의 가독성, 한글 IME 확정·취소, 전체화면/Spaces, Retina 정밀 좌표, 모니터 연결 변경.

- Windows 실기는 준현님 요청에 따라 이후 진행한다. Windows 소스 경로가 존재하는 것을 실기 지원 확인으로 표시하지 않는다.

성능의 실제 측정 조건과 수치는 [성능 기록](performance.md)에 별도로 기록한다. 혼합 부하나 짧은 측정을 통제된 유휴 성능 합격으로 해석하지 않는다.
