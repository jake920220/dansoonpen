## v0.3 강의 사용성 확장 (2026-09-08)

순서대로 한글 도구 키·측정 도구 보강, 필기 숨김·복원, 선택한 화면 삭제, 커서 강조·클릭 표시를 기능별 커밋했다. 설정 기본값은 그대로 보존했다(이 기기의 기존 저장값은 노란 14px, 새 설치 기본값은12px).

### 실제 앱에서 확인한 범위

- 최종 macOS arm64 release의 Info.plist·시작 UI 모두0.3.0, 준비 완료. 새 도구막대와 C 키의 커서 켜짐 상태·노란 강조 원을 확인했다.
- 동일 기능 코드에 임시 전환 로그만 추가한 검사 빌드에서 기본 모니터에 한 획을 작성했다. 숨김 버튼을 누르면 선·도구막대가 사라지고 입력을 받지 않는 창 상태로 바뀌었다. 제어창의 ‘숨긴 필기 다시 표시’를 누른 뒤 그리기로 돌아오면 같은 선1개가 복원됐고 undo0개→redo1개로 기록 보존을 확인했다.
- ‘이 화면만 지우기’ 후 비입력 창으로 전환되고, 재진입0개→undo1개를 확인했다. 다른 화면의 진행 중 편집 보존 및 선택/전체 삭제의 혼합 세대·undo/redo 범위는 Rust 검사로 검증했다. 두 화면에 실제 선을 그린 교차 검증은 아직 완료하지 않았다.
- 실제 선택을 100% 기본 화면→2940×1912/200% Retina→기본 화면으로 바꾸고 기존 기본 화면의 선이 남는 것을 확인했다. Retina 캡처에서 검사 도구의 ScreenCaptureKit -3811 오류가 발생해 해당 화면의 실제 필기·커서 좌표 판정은 보류했다.
- macOS 입력 소스가 두벌식 한글인 상태에서 T 키로 텍스트 도구가 선택되는 것을 확인했다. 한글 문장의 직접 조합·마지막 받침 확정은 완결된 검사로 기록하지 않는다.
- 자동 검사 중 수동 입력이 섞여 상태가 달라졌다. 임시 로그에서 문제 삼았던 모드 복귀 시점은 삭제 명령 경로였고, 추적 구간에서 시간만으로 삭제되는 경로는 관찰하지 않았다. 원인을 추측해 제품 동작을 바꾸지는 않았다.
- 검사 로그 코드는 제거했고 일반 release를 다시 설치했다. 최종 release의 그리기 진입0개→Esc 입력 복귀를 다시 확인했다. 검사 도구·개발 서버는 배포물에 포함하지 않는다.

- v0.3.1은 진단 기능을 추가한 빌드다. 알려진 배율·활성화 순서 문제를 추측으로 수정하지 않았고, 검은 화면 재발 방지를 검증한 결과가 아니다. 이번에는 GUI를 실행하거나 강의 화면공유를 재현하지 않았다. 다음 실제 실행부터 로그가 생성된다.

## v0.4.0 삭제 효과·텍스트 편집·글꼴 (2026-09-08)

- 준현님의 9.153초 영상에서 지우개로 없어진 필기가 삭제 확정 때 다시 나타나는 동작을 확인했다. 포인터가 닿을 때 220ms 페이드를 시작하고, 이후 네이티브 삭제 응답에서는 같은 효과를 반복하지 않게 했다. 전체 삭제 350ms와 새 필기 보존은 유지한다. 부드러운 시작·끝의 opacity 곡선을 적용했다.
- 텍스트 도구로 기존 글의 어느 줄을 눌러도 재편집한다. 동일 주석 ID·위치·크기·색상·겹침 순서를 유지하고, 교체는 한 번의 undo/redo 작업이다. 취소·변경 없는 완료는 원문을 유지한다. 빈 내용으로 완료하면 삭제한다. 전체 삭제 후 늦은 수정이 도착해도 글을 되살리지 않는다.
- 기본 글자 크기는 28→40px, 기본 메모 프리셋은 32→44px. 설정 버전 4에서 이전 기본값만 이전하며 다른 사용자 지정 크기와 변경한 프리셋을 보존한다. 이 기기의 노란 펜 14px 기본값도 보존 대상이다.
- 나눔고딕 Regular 원본 2,054,744바이트를 로컬 번들에 포함했다. SHA-256은 `76f45ef4a6bcff344c837c95a7dcc26e017e38b5846d5ae0cdcb5b86be2e2d31`. 폰트 초기 로드를 기다린 후 텍스트 측정을 시작하고 textarea·Canvas의 기준선을 맞췄다.
- Google Fonts 원본 커밋과 폰트·메타데이터·OFL SHA-256을 SOURCE.json에 고정했다. 원본 OFL의 공백도 보존했으므로 해당 파일의 upstream 후행 공백 2곳은 의도된 원본 보존이다. 고지 생성기는 폰트 해시와 전문을 검증하며 앱 리소스에도 OFL을 별도 포함한다.

### 자동 검사 및 미리보기

- 프런트엔드 43개, Rust 37개 통과. Svelte 오류·경고 0, fmt·strict Clippy 통과. 기존 의존성 303개 고지와 추가 폰트 원문·해시 일치.
- 렌더러: 늦은 삭제 응답이 fade를 밝게 만들거나 기간을 재시작하지 않음, 새 필기 유지, undo 복원, 비활성 후 fade 정리 및 CSS 행 기준선 정렬.
- 모델: 텍스트 교체의 ID·순서·undo/redo·clear barrier, 중복 ID·잘못된 종류의 교체 거부. 설정: 기본값 이전·사용자 설정 보존·한 번 저장한 현재 버전의 28px 재설정 보존.
- 브라우저 미리보기: 여러 줄 한글 입력 → 두 번째 줄 클릭으로 기존 내용 재편집 → 수정 완료 후 객체 수 1개 유지 → undo로 원문 → 편집 중 Esc 취소 → redo로 수정본 복원. 40px 나눔고딕과 확정 전후 글자 위치를 시각 확인했다. 브라우저 검사는 OS 창 입력이나 전역 키 검증을 대체하지 않는다.

### macOS 실행 및 남은 실기 검사

- 실제 v0.4.0 macOS arm64 release 빌드와 앱 실행, 그리기 오버레이 진입을 확인했다. 기존 v0.3.1은 필기 0개·interact 상태를 확인한 뒤 종료했다. 실행용 앱을 기존 경로에 교체하고 이전 앱은 휴지통에 보관했다.
- 실제 창 검사 도중 별도 입력으로 그리기 모드가 종료되어 조작 충돌을 피하려고 일시 중단하고 사용자에게 검사 지속 여부를 물었다. 네이티브 재편집·한글 IME 조합·새 fade의 실제 프레임 품질은 아직 이 단계에서 합격으로 표시하지 않는다.
- Windows 실제 실행, 강의 화면공유 수신 화면, 혼합 DPI의 정밀 배치는 미검증이다. 이전 단축키/검은 화면 사건의 해결을 이번 변경으로 주장하지 않는다.

- 버전 표기를 package.json에서 읽도록 수정한 최종 앱·ZIP도 준비했다. 실행 중인 세션은 유지하고 디스크의 실행용 앱만 교체했으므로, 최종 버전 표시는 다음 재실행에 적용된다. 기능 코드·폰트는 이미 실행 중인 v0.4.0과 같다. 설치 앱을 ad-hoc 재서명 후 strict 서명 검증했으며 ZIP CRC와 라이선스 리소스 4개를 대조했다.
