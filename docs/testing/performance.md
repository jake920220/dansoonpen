# macOS 성능 검증

200MiB 메모리·정지 CPU 1%·렌더 p95 16.7ms는 계획의 목표이며 Tauri의 보장값이 아니다. 아래에서 실측과 구조상 제한을 구분한다.

## 확인한 구조

- 포인터마다 Rust IPC를 보내지 않으며 완료된 획/편집만 전달한다.
- 정지 상태에서는 CanvasRenderer가 RAF를 예약하지 않는다(단위 검사).
- 화면 오버레이는 처음 사용하는 모니터에 생성한다. 장면 변화·입력·fade·resize에서만 렌더를 예약한다.
- Rust는 주석 payload를 Arc로 공유한다. undo 최대128개/보수적 데이터128MiB, 현재 장면 데이터64MiB 제한이다. 이 수치는 프로세스 RSS나 GPU 메모리 상한이 아니다.
- fade는 임시 객체·점 비용과 길이를 제한한다. 시간 지연 후에도 경과 시간에 따라 종료한다.
- 화면 연결 변경은 3초 주기로 확인한다. 지속 캡처/네트워크 전송은 구현하지 않는다.

## 단위 부하 측정의 해석

Apple M2 / macOS 26.6.2의 Node 가상 Canvas context에서 1,000획(100,000점)+100텍스트를 처리했다. 렌더 호출 median 8.20ms/p95 21.92ms, 지우개 검색 median 9.34ms/p95 29.48ms였으며 실행 종료 시 pending RAF는0이었다. 다른 빌드 작업이 동시에 있었고 GPU·실제 Canvas 래스터화를 포함하지 않는다. 따라서 A14 지연 목표의 합격 결과로 사용할 수 없다.

Rust의 1,000획/100,000점과 20회 clear/undo 검사는 장면 및 참조 데이터가 제한 안에서 유지되는지를 검증한다. 실제 4K 두 화면의 메모리 누수를 판정한 결과가 아니다.

## 실제 측정 절차

초기 release 프로세스의 1회 스냅샷: 실행 후 1분28초 시점에 주 프로세스 RSS 102,960KiB(약100.5MiB), `ps`의 CPU 표시0.0%. **WebView/GPU 프로세스를 합산하지 않았고 5분 평균도 아니므로 A12/A13 합격 근거가 아니다.** 앱 번들 디스크 크기는 약14MiB이며 런타임 메모리와 다른 수치다. 주 프로세스의 `lsof -i`에 연결은 없었지만 하위 프로세스 전체와 장시간 네트워크 관찰은 미완료다.

release 앱에서 60초 안정화 후 5분간 정지 상태를 관찰한다. 기본 장면과 1,000획/100,000점+100텍스트, 1080p 한 화면과4K 두 화면을 분리한다.

- CPU: 주 프로세스와 귀속된 WebView/GPU 프로세스의 CPU 시간 증가량을 합산하고 벽시계 시간으로 나눈다. 코어 수로 나누지 않은 단일 코어 기준을 사용한다.
- 메모리: macOS RSS, Windows working set을 프로세스별로 기록하고 합계·공유 메모리 중복 가능성을 명시한다. WebView 프로세스 귀속을 확인하지 못하면 전체 앱 수치라고 표시하지 않는다.
- 전환: 20회 전환·실행의 p95를 기록한다. 내부 렌더 시간과 실제 포인터→화면 지연을 구분한다.
- 강의 부하: 같은 AI/프로그램 부하와 화면공유에서 앱 사용/미사용을 교대로 측정한다. 수신 프레임 누락을 계측할 수 없다면 수치 합격을 주장하지 않는다.

Windows·4K 복수 화면·실제 회의 부하의 숫자 측정은 미완료다. 정확한 수신 측정 없이 ‘프레임 저하 없음’으로 표현하지 않는다.

## 재현 가능한 macOS 측정

`scripts/measure-macos.py --pids <쉼표로 구분한 PID> --condition <측정 조건과 귀속 근거> --output artifacts/measurements/idle.json`으로 5분간 5초 간격의 RSS와 누적 CPU 시간을 기록한다. 별도 패키지는 필요 없다. 프로세스가 종료되면 불완전한 합계를 만들지 않고 실패한다. WebKit XPC의 PPID는 launchd이므로 PPID만으로 귀속시키지 않는다. 앱 종료 전후 PID 소멸 여부 등 독립적인 귀속 근거를 함께 기록해야 한다.

한글 입력기 사용 시 도구/색/굵기와 undo의 문자값 대신 물리 키 위치를 사용하도록 보강했다. 입력칸·IME 조합 중에는 도구 키를 가로채지 않는다. 이는 단위 검사이며 실제 IME 확정/포커스 검증과 별개다.
