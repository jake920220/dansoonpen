# 모든 연결 화면 필기 — 2026-09-15

준현님의 요청에 따라 v0.5.1 (`4b00142`)을 기준으로 `codex/all-displays-drawing`에서 v0.6.0을 준비했다. 계기는 [수면 복귀 후 그리기 실패](incident-2026-09-15-sleep.md)다.

## 변경 동작

- 그리기 시작 시 연결된 모든 모니터에서 입력을 받는다. 설정창·도구막대의 화면 선택과 네이티브 선택 상태를 제거했다.
- 최초 키보드 포커스는 커서가 있는 화면으로 보낸다. 다른 화면에서는 첫 클릭부터 그리며 도구·색상·크기를 공유한다. 도구막대 위치와 필기는 화면별로 유지한다.
- “이 화면만 지우기”는 누른 도구막대의 화면만 지운다. 전체 삭제와 시간순 undo/redo는 기존 의미를 유지한다. 커서 강조는 화면별로 갱신하고 이전 화면의 원을 숨긴다.
- 연결 변경 시 남은 화면의 그리기를 유지하고 돌아온 화면에도 같은 모드를 적용한다. 모든 화면이 끊긴 경우 입력을 해제하고 앱 조작 모드로 복귀한다. 연결 변경으로 필기를 삭제하지 않는다.
- macOS는 대상 모니터 배율로 계산한 전체 창 프레임을 동기 적용한다. 화면을 표시하는 작업은 포커스를 바꾸지 않는다. 그리기 진입 시 앱 활성화 후 필기 창·WebView 순서로 포커스를 지정한다. AppKit 활성화가 콜백 이후 완료될 수 있어 즉시 key=false라는 이유로 그리기를 취소하지 않는다.

## 실제 OS 검증

2026-09-15 09:08에 최종 수정본을 기존 실행 경로에 적용하고 UI의 v0.6.0 및 “2개 화면 · 커서를 옮겨 바로 그리세요”를 확인했다. 최초 적용본은 비동기 활성화 직후 key=false를 실패로 처리하는 문제가 드러나 NSApplication 자체 활성화 경로를 사용하고 성급한 실패 판정을 제거한 뒤 재빌드·재적용했다. Clippy·Rust 47개 검사·macOS release 빌드를 다시 통과했다.

최종 세션 `1789430923194-42657`에서 그리기 진입 4회와 앱 조작 복귀 4회가 오류 없이 완료됐다. 각 Draw에서 두 창 모두 ignoresMouse=false, 각 Interact에서 모두 true였고 크기·위치는 외부 화면 AppKit (0,0,2560,1440), Retina (2560,0,1470,956)로 유지됐다. 세 번째 진입의 즉시 key=false 표본 뒤 38ms 후 필기 창 focus=true 이벤트가 발생했고 frontend도 focused=true를 확인했다. 외부 화면 필기 1개가 모드 복귀 후 유지되는 로그도 확인했다.

자동 UI 클릭 시 사용자 입력에 따른 상태 변경 경고가 있어 추가 마우스 조작을 멈추고 실제 세션 로그로 판정했다. 따라서 Retina의 실제 첫 획·지우기·텍스트와 화면 사이 도구 공유를 시각 검증했다고 주장하지 않는다. 장시간 실제 수면, 물리적 케이블 재연결, Windows, 화면공유 수신 화면은 별도 검증이 필요하다. 최종 세션 로그는 `artifacts/all-displays-final-session.jsonl`에 보존했다.
