## 진행 순서

1. 기본 펜 재진입: 실제 모드 진입에서만 초기화. 늦은 도구 변경 응답이 기본값을 덮지 않도록 검증.
2. 지우개 크기 분리: 펜/형광펜 굵기와 독립, 기존 설정 및 프리셋 호환.
3. 빠른 크기 조절: 도구별 작은/중간/큰 값과 미리보기, 텍스트의 `[ ]` 처리.
4. 기존 텍스트 이동·크기·색 수정: 취소/IME/undo/clear barrier와 화면 경계 보존.
5. 간단 도구막대: 더보기로 확장 도구 접근, 기존 이동/접기/위치 복원 보존.
6. 모드 전환·삭제 결과 안내: 완료된 상태 기반 안내, 삭제 되돌리기, 앱 조작 중 입력 통과 보존.

## 공통 검증 기준

- 최종 전체 테스트, fmt/clippy, 고지 일치, production 및 macOS 빌드를 확인한다.
- UI 흐름과 네이티브 입력/포커스/투명도 검증을 구분한다. Windows 및 공유 수신 미검증은 그대로 표시한다.
- 시간 경과/모드 전환으로 필기를 지우지 않는다. 삭제 후 새 필기는 보존한다.

## v0.5.1 — 삭제 시 현재 모드 유지 (후속 요청)

준현님의 후속 요청에 따라 위 v0.5.0의 삭제 후 interact 전환 정책을 변경했다.

- 전체 삭제 단축키·휴지통·트레이와 선택 화면 삭제는 필기만 지우고 모드·선택 도구·메뉴 독·네이티브 입력/포커스를 유지한다. 빈 화면에서도 모드를 바꾸지 않는다.
- clearGeneration 증가, 진행 중 편집 취소, 수동 fade, 새 필기 보존, 삭제 복구 이력은 유지한다. 그리기 종료는 기존 Alt+Z/Option+Z 및 Esc·앱 조작 버튼 경로가 담당한다.
- 프런트엔드 52개·Rust 44개, Svelte 오류/경고 0, Rust fmt·strict Clippy 통과. macOS arm64 v0.5.1 release 빌드 및 설치 앱 서명 검증 완료.
- 실제 앱에서 펜 한 획 작성 → 텍스트 도구 선택 → 휴지통 클릭 후 객체 수 1→0, 텍스트 선택 on, 메뉴 독 표시가 유지됐다. 진단 로그 clear_complete도 draw였다. 약 3.8초 뒤 별도 Alt+Z 입력을 받아 interact로 전환됐다.
- 앱 조작 중 Alt+X 수신 시에도 interact가 유지되는 것을 로그로 확인했다. 단축키·휴지통·트레이가 같은 삭제 함수를 호출하는지 코드에서 확인했다. 그리기 중 물리 Alt+X의 통제된 반복 검사는 별도 진행하지 않았다.
- 후속 빈 화면 삭제/즉시 이어 그리기 검사 중 외부 모드 전환으로 접근성 요소가 사라져 추가 조작을 중단했다. 해당 시나리오의 네이티브 실기 완료로 기록하지 않는다. 기존 모델 검사는 빈 장면의 세대 증가·늦은 편집 거부·새 필기 보존을 확인한다.
- 실행 앱은 기존 `artifacts/My Brush.app`에 교체했고 이전 번들은 휴지통에 보관했다. 로그는 Git 제외 `artifacts/clear-mode-20260909/diagnostics.jsonl`에 보관한다. Windows 및 기존 간헐적 장애의 검증 범위는 확대하지 않았다.
