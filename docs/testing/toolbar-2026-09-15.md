# 모니터 사이 도구 패널 이동 — v0.6.1

준현님은 다른 모니터에 있는 도구 패널을 메인 모니터로 끌어올 수 없다고 보고했다. 기존 ToolbarFrame은 화면별 WebView 안의 위치를 현재 viewport 범위로 제한했으므로 경계를 넘을 수 없었다.

## 구현

- 도구 패널을 한 화면에만 표시하고 손잡이의 pointer capture를 유지한 채 다른 화면으로 이동한다. 원래 창의 숨은 패널 DOM은 드래그가 끝날 때까지 유지한다.
- 원본 포인터 이벤트의 창 내부 좌표를 화면 좌표로 환산한다. macOS의 논리 좌표와 Windows의 물리 좌표를 구분한다. 비동기 처리 중 현재 커서 위치를 다시 읽으면 드롭이 어긋날 수 있어 이벤트에 기록된 좌표를 사용한다.
- 이동 요청을 프레임마다 합치고 한 번에 하나만 처리한다. 드래그 종료 때만 화면·정규화 위치·접힘·더보기를 settings.toolbar에 원자 저장한다.
- 기존 설정에는 기본 패널 위치를 보충하며 다른 펜 설정 변경은 패널 위치를 보존한다. 선호 화면이 잠깐 끊기면 기본 화면에 표시하고 재연결 시 선호 화면으로 돌아간다.
- 오래된 드래그 token·다른 창의 이동은 무시하고 모드 종료 및 화면 구성 변경 시 드래그를 취소한다. 텍스트 편집창 자체의 색·크기 도구는 유지한다.

## 검사 결과

- 프런트엔드 55개, Rust 52개 테스트 통과. 기본 화면/선호 화면 복원, 혼합 배율 양방향 좌표, 경계 제한, 오래된 드래그 차단, 구 설정 로드·저장·다른 설정 변경 시 보존 포함.
- Svelte 오류·경고 0, Rust fmt·Clippy, 의존성 고지 일치, macOS arm64 release 빌드·로컬 패키지 서명 검증 통과.
- 실제 macOS에서 1x 외부 모니터 안의 패널을 드래그한 뒤 놓은 위치에 유지되는 것을 확인했다.
- **외부 모니터 → 2x Retina → 외부 모니터**의 드래그를 실제 UI로 수행했다. 원래 화면에서 패널이 사라지고 대상 화면에서 같은 패널이 표시되는 것을 각각 AX·스크린샷으로 확인했다. Retina에서 패널을 직접 클릭해 조작할 수 있었다.
- 메인 모니터 상단으로 돌려놓고 앱 조작 모드 → 그리기 재진입 후 같은 위치로 복원되는 것을 확인했다. 마지막에는 앱 조작 모드로 복귀했다.
- 앱 재실행 시 이전 저장 위치 복원도 관찰했다. 기존 노란 14px 펜과 그리기·삭제 단축키는 유지했다. 디스크의 원본 설정은 v3였으므로 패널을 처음 저장할 때 기존 로더가 이미 메모리에 적용하던 v5 마이그레이션도 함께 저장됐다(40px 글자·프리셋 기본 글자 크기·독립 지우개·커서·숨김 기본값). 이는 검사 전 실제 설정 UI에 표시되던 값과 같다. 이전 앱과 원본 설정을 함께 백업했다.

최종 앱은 기존 `artifacts/My Brush.app` 경로에 적용했다. ZIP은 작업 트리의 `artifacts/My-Brush-0.6.1-macOS-arm64.zip`, 설치 이력·이전 앱/설정 백업 경로는 `artifacts/toolbar-0.6.1-install.json`, 실제 세션 로그는 `artifacts/toolbar-0.6.1-native-session.jsonl`에 보존했다.

물리적 케이블 재연결·장시간 수면 복귀·Windows 실기는 이번 검사에 포함하지 않았다. Windows 좌표 단위 검사는 실제 OS 입력 검증을 대체하지 않는다.
