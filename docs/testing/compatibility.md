# v0.1 호환성·실기 기록

날짜: 2026-09-08. 이 문서는 구현 여부와 실제 실기 통과를 구분한다. 미검증 항목은 지원 보장으로 취급하지 않는다.

## 환경

- 로컬 빌드/실기: Apple M2, macOS 26.6.2 (25G83), arm64, Rust 1.94.1, Node 26.4.0.
- 최소 macOS 설정: 13.0. 현재 호스트 외의 OS 버전·Intel Mac은 미검증.
- Windows 11 x64: 준현님이 직접 테스트할 PC가 있음. 에이전트에게 원격 실행 환경은 제공되지 않았으므로 Windows 빌드·설치·실기는 대기.
- 회의 앱과 수신 기기는 아직 연결하지 않음. Zoom·Meet 수신 화면 통과를 주장하지 않음.

## 자동 검사

Canvas 단위 검사: 곡선/한 점 획/텍스트 hit test, 지우개 이동 경로, 고해상도 좌표, 입력 합치기, 정지 시 RAF 없음, fade 중 새 객체 유지, undo 복구, 시간 지연 후 fade 종료, fade 메모리 제한, dispose.

Rust 단위 검사: 전역 다중 화면 clear/undo, Arc 공유, 이력 제한에서 현재 필기 보존, 무효 편집 원자성, 1,000획·100,000점 부하, 설정 round-trip, 단축키 등록·해제 실패 롤백. 삭제 세대·한글 길이 회귀 검사도 포함한다.

최종 결과: 프런트엔드 14개, Rust 17개 테스트 통과. Svelte 오류/경고0, strict clippy와 fmt 통과. 실제 LICENSE·NOTICE·의존성 고지를 포함한 macOS release `.app` 빌드 성공. 독립 아키텍처 검토 APPROVE.

## 실제 macOS 앱 확인

- 에이전트: 설치용 release 앱을 실행하여 `tauri://localhost` 제어 화면의 준비 완료와 2560×1440/100% 기본 화면 인식을 확인했다. 그리기 시작으로 실제 오버레이와 도구막대, 다중 화면 선택기가 표시되었다.
- 준현님 직접 확인: **“투명한 화면 위 필기·뒤 앱 조작 모두 정상”**. 질문은 선을 그린 뒤 Esc를 누르면 그림이 유지되고 뒤 앱을 조작할 수 있는지였다.
- 이 확인은 핵심 흐름의 수동 smoke test다. 100회 반복·30분 유지·실제 IME·전체화면·프로젝터·회의 수신 확인은 아직 수행했다고 기록하지 않는다.
- ZIP용 앱 사본은 로컬 ad-hoc 서명 후 `codesign --verify --deep --strict` 통과. Developer ID 서명과 Apple 공증은 수행하지 않았다.
- 번들의 LICENSE·NOTICE·THIRD_PARTY_NOTICES.txt SHA-256이 저장소 원본과 각각 일치했다.

## 브라우저에서 확인한 흐름

Codex 내장 브라우저, 1280×720의 개발용 미리보기에서 다음을 확인했다.

- 시작 화면과 그리기 도구막대 표시
- 선 추가 후 유지, 한글 문자열 붙여넣기·Enter 확정·캔버스 표시
- 전체 삭제 시 객체 수 0, 실행 취소 시 기존 2개 복구
- Esc로 조작 모드 전환 후 그림 유지

브라우저 붙여넣기는 실제 한글 IME 조합 테스트가 아니다. 브라우저 캔버스는 OS 위 클릭 통과를 입증하지 않는다.

## Windows에서 실행할 검사

1. README의 Windows 사전 준비를 완료하고 프로젝트 폴더를 복사한다. VS C++ Build Tools, Rust MSVC, Node, WebView2가 필요하다.
2. PowerShell에서 `./scripts/verify-windows.ps1`을 실행한다. 시스템 정책이 스크립트 실행을 제한하면 전역 정책을 바꾸는 대신 README의 명령을 하나씩 실행한다.
3. `src-tauri/target/release/bundle/nsis/`의 설치 프로그램으로 설치한다. 새 설치와 재실행을 구분해서 기록한다.
4. 아래 시나리오를 실제 앱에서 검사한다. 결과 로그는 `artifacts/windows-check-*.log`에 생성된다.

## 강의 시나리오 체크리스트

| 검사 | 절차 | 합격 조건 |
| --- | --- | --- |
| 유지·조작 | 선과 텍스트 작성 → Esc → 뒤 브라우저 링크 클릭·스크롤·드래그·키 입력 | 필기가 유지되고 뒤 앱만 입력을 받음 |
| 전역 키 | 다른 앱이 앞에 있을 때 모드 키·삭제 키, 키 누르고 유지 | 1회 전환, 삭제 키 전까지 유지, 반복 토글 없음 |
| 삭제 경계 | 펜을 누른 채 삭제 키 → 마우스 놓기; 텍스트 편집 중 삭제; 삭제 직후 새 선 | 삭제 전 편집이 재등장하지 않고 새 선은 유지 |
| undo/redo | 두 화면 필기 → 전체 삭제 → undo → redo | 두 화면을 한 작업으로 복구·삭제 |
| 한글 IME | ‘강의 자료를 설명합니다’ 직접 조합, 받침 수정·한영 전환·줄바꿈·Enter·Esc·모드 키 | 마지막 글자 손실·문자키 도구 오작동 없음 |
| 설정 | 색·굵기·키 변경 → 앱 종료·재실행, 키 충돌 유도 | 설정 유지, 충돌을 알리고 트레이로 복구 가능 |
| 전체화면 | Mac 브라우저/Keynote, Windows 브라우저/PowerPoint 슬라이드쇼 | 현재 전체화면을 유지하며 그리기·조작·삭제 가능 |
| 디스플레이 | Retina/일반 화면, Windows 100/125/150/200%, 음수 원점 | 좌표가 일치하며 선택 화면만 입력 받음 |
| 연결 변경 | 확장·미러링·연결 해제/복구 10회 | 입력을 막는 고아 창 없음, 같은 ID의 장면 복구 |
| 공유·빔 | Zoom/Meet에서 모니터 전체 공유, 다른 기기로 수신, 빔 연결 | 수신 화면에 선·한글·fade가 보임 |
| 장기 사용 | 30분 유지, 앱·모드 전환 각각100회 | 명시적 삭제 외 소멸 없음, 입력 복구 실패 없음 |

기록 시 OS·CPU·메모리·화면 해상도/배율·회의 앱 버전·수신 장치·재현 순서·예상/실제 결과를 남긴다. Windows UAC와 보안 데스크톱, DRM, 게임 독점 전체화면은 이 버전의 보장 범위에서 제외한다.

화면 ID가 OS에 의해 바뀌는 장치(익명 디스플레이, 출력 포트 재배치 등)는 재연결 후 기존 장면으로 식별하지 못할 수 있다. 재시작 후 그림 복구는 구현하지 않는다.
